# ADR-0002: Границы модулей — schema per module, зависимость только от Contracts

- **Status:** Proposed
- **Date:** 2026-09-30
- **Stage:** 1
- **Related:** requirements §12.1, §12.2, §13; domain-model §2; ADR-0001, ADR-0010

## Problem

В модульном монолите с одной БД границы модулей легко размываются: прямые ссылки на чужие классы, JOIN по
чужим таблицам, общие EF-контексты. После этого модуль нельзя изменить или выделить без каскадных правок.

## Constraints

- Модули должны иметь явные границы, понятное владение данными и минимальную связанность (§12.1, §12.2).
- Cross-module SQL dependencies минимизируются (§12.2).
- Нельзя усложнять систему распределёнными транзакциями.

## Options

1. Модули как папки в одном проекте, границы поддерживаются соглашением.
2. Проект на модуль плюс отдельный проект `.Contracts`, отдельная схема БД на модуль, архитектурные тесты.
3. Разбиение каждого модуля на 4+ проекта (Domain / Application / Infrastructure / Api).

## Decision

Вариант 2:
- Модули соответствуют bounded contexts из domain-model: Conversations, Support Organization, Identity,
  AI Assistance, Notifications, Audit, Reporting.
- Модуль зависит **только от `*.Contracts`** другого модуля (integration events, query interfaces).
- **Schema per module.** Нет cross-schema FK и JOIN, связи только по ID. Исключение описано в ADR-0010.
- Синхронные межмодульные вызовы допускаются **только для чтения**. Изменения в другом модуле происходят
  через integration events (ADR-0003).
- Правила проверяются архитектурными тестами в `tests/SupportFlow.ArchitectureTests`.

## Trade-offs

**Плюсы:**
- Нарушение границы по коду ловит компилятор или тест, а не code review.
- Владение данными однозначно: у каждой таблицы ровно один модуль-владелец.

**Минусы:**
- Нет FK между схемами. Целостность ссылок между модулями обеспечивает приложение.
- Запросы, которым нужны данные нескольких модулей, собираются в приложении или через контрактные views,
  а не одним JOIN.
- Больше проектов в solution (2 на модуль). Вариант 3 отвергнут как избыточный для текущего размера.
